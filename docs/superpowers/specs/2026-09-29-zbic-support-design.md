# Managed ZBIC Decoder Design

## Goal
Add Nintendo ZBIC frame decompression to the managed ZstdSharp fork so Ryubing/LibHac can decode HOS 22+ ZBIC-compressed NSO segments without a native C dependency.

## Scope
This branch changes `Masamune3210/ZstdSharp` only. LibHac integration remains a separate follow-up after the decoder is proven.

Initial scope is **decompression only**. Compression support is not required for NSO loading and is intentionally deferred.

## Reference implementations
The implementation is based on the same Zstandard 1.5.7 lineage already used by ZstdSharp:

- Atmosphere ZBIC support: patched Zstandard 1.5.7 with `ZSTD_ZBIC_SUPPORT` enabled.
- `kinnay/zbic`: packages Atmosphere's patched Zstandard implementation.
- `pladaria/nixe` vendored `ruzstd-zbic`: independent MIT-licensed implementation documenting the two format changes relevant to decode: ZBIC frame magic and binary-interpolative normalized FSE probability tables.

These are references for behavior. ZstdSharp remains the implementation base.

## Format behavior
ZBIC retains ordinary Zstandard frame/block structure but differs in the pieces relevant to this decoder:

1. Frame magic is little-endian `0x4349425A` (`ZBIC`) rather than standard Zstd `0xFD2FB528`.
2. Normalized FSE probability tables are encoded with Nintendo's binary-interpolative cumulative representation instead of standard `FSE_readNCount` representation.

All remaining decompression behavior should continue through existing ZstdSharp code paths.

## Architecture
Add ZBIC as an explicit decode mode rather than globally changing Zstd constants. Standard Zstd decoding must remain byte-for-byte behavior-compatible with upstream ZstdSharp.

The mode is selected at frame parsing from the input magic and propagated only to code that reads normalized FSE counts. ZBIC frames call a dedicated BIC normalized-count reader; standard frames continue calling the existing `FSE_readNCount` implementation.

Public API should expose a small ZBIC-specific entry point rather than making ordinary `Decompressor` silently accept Nintendo frames. This keeps the fork's behavioral extension explicit for LibHac.

## Validation
Tests must use deterministic ZBIC vectors generated by an independent implementation, not by the new C# implementation itself. At minimum:

- a small generated ZBIC frame decompresses to known bytes;
- a vector exercising a compressed block/FSE probability table decompresses correctly, so the test is not satisfied by only swapping frame magic;
- malformed/truncated BIC table input returns a decompression error rather than reading out of bounds;
- ordinary Zstd tests continue to pass unchanged.

For provenance, test vectors should record the generator/reference implementation and exact source revision used to produce them.

## Non-goals
- No ZBIC compression in the initial implementation.
- No NSO parsing changes in this repository.
- No native bridge, P/Invoke, CMake, or platform-specific binaries.
- No changes to upstream standard-Zstd wire behavior.
